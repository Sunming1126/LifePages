# 书架上线与旧聊天迁移

新版 App 首次访问 `GET /api/books` 时初始化书架。空账号直接得到《我的回忆录》。有旧聊天或章节的账号需要显式启用 `LIFEPAGES_ALLOW_BOOK_MIGRATION=1`，否则接口返回 503 并保留旧数据。

1. 在脱敏数据副本上执行 `python -m unittest server.test_books` 对应的迁移、清理、章节隔离及二维码验收。正式发布前用 SQLite 在线备份分别快照 LifePages 注册库和账户库，并保留与数据库配套的录音文件和当前版本指针。备份目录仅限服务器管理员访问。
2. 将代码发布到新的 LifePages 版本目录，保留已有 `bin/qdrant`、部署配置、服务环境和共享数据。在服务器上先运行隔离数据的验收测试。暂停 LifePages 写入和定时任务，确认备份有效后，仅在一次性迁移进程中启用迁移开关。核对迁移结果后切换 API，再用隔离账号验证书架、章节和草稿接口。现有 API 兼容未迁移的账号。已迁移的账号须使用新版 App 继续创作。
3. 初始化在账户 SQLite 事务内清除旧会话和旧记忆，保留非空章节及章内原声。保留原声用的数据库行会清空旧文字并改成不可用于聊天的角色，已有二维码仍指向原 ID。老录音、向量和分享索引的清理任务在同一事务入队，由原有记忆任务重试。30 天到期删书也走这套任务。
4. 迁移后的回退需要恢复配套数据库和录音备份，并从 SQLite 重建记忆向量索引。仅切回代码版本无法恢复已清除的旧聊天。回退操作只作用于 LifePages。

## 2026 年 11 月 6 日线上迁移

- 线上版本为 `/opt/lifepages/releases/20261106-221947-books`，数据库和原声备份位于 `/opt/lifepages/backups/20261106-221947-books`。
- 迁移了 1 个账号的 1 本书，生成 26 个采访章节。核对了原有 1 篇成稿的 ID 与正文，并校验 1 段关联原声的文件摘要。
- 清除了 5 条旧聊天消息、1 条旧长期记忆及其向量索引。线上已有的录音均被成稿引用，迁移前无已签发的分享链接。旧二维码兼容性通过测试数据验证。
- 在目标服务器通过 20 项后端测试。线上隔离账号通过默认书、重复打开章节、草稿读取和删书恢复验证。LifePages 定时任务已恢复，共享网关配置和检查范围内的其他服务进程未发生变化。
