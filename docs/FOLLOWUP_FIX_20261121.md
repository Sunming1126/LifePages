# 灶台短对话追问修复

开发分支：`ios/interview-theme-v2`，基线 `e9e3ffd`。后端源码在 `/Users/zhaoqing/.codex/worktrees/lifepages-interview-v2/LifePages`；实际 iOS 编译目录为 `/Users/zhaoqing/myprojects/LifePages`，本轮没有用后端源码覆盖原目录的账号会员工作。

## 已复现问题

截图中“本题已记录”、旧开场以及“我们可以接着聊刚才这段往事。”对应旧访谈 v1。`server/interview.py` 在 `off_topic` 时直接返回写死的催聊话，原提示词还禁止生成回复，只允许挑选固定选项。因此仅隐藏客户端目录不能改善该书的追问。

真实模型隔离验收还发现：备用题可能再次征求许可；无效的多问题追问在 v2 被当作当前故事无追问价值，直接换了入口；把“可以啊”交给素材判断可能产生格式错误或误计字数。失败候选均未切换生产，合成账户均清理。

## 最终行为

- v1 优先采用基于用户原话生成、经过校验的具体追问；固定题只作备用，删除空泛催聊出口。
- “可以啊”“好”“您问吧”等简短同意语走独立分支，保留原有素材和进度，直接根据上下文生成另一个容易回答的细节，不误判为离题，不计入成章字数。
- 新的短回忆线索至少先尝试一次贴着原话的追问；线索暂未成为可成章素材时，仍保留其探索价值，不计为连续无新增。
- 追问比较忽略“当时”“具体”等礼貌和修饰词，避免加字复问同一细节。
- v2 遇到模型生成多问、征求许可或重复的问题，先针对性修正追问；不直接丢掉正在讲的故事。
- 追问生成与验收判断使用不同输入：生成只携带对话和已问记录，不再混入整套验收结构。模型产生三个不同焦点的候选，程序只选一条有效、未出现的问题展示；必要时携带具体无效原因纠正一次。
- 用户没有确认过的助手假设不能当作事实。
- 不完整的素材判断进行一次带明确格式反馈的纠正；未得到充分证据仍不能正常完成主题，301 字门槛不变。
- 连续同意而没有新增内容的 v2 对话仍遵守两轮无新增后换入口的规则。
- 旧书不迁移、不删除；新建 v2 书使用隐藏主题机制，旧书也移除了这次复现的催聊出口。
