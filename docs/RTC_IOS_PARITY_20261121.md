# iOS / 安卓 RTC 预连接一致性修复

## 原因与范围

此前虽共享 `RtcReplyPlayer`，`_preconnectReplyAudio()`、预连资源释放和授权/音色变更监听仍受 Android 条件限制，iOS 没有启用预连接。已将入口扩展到 iOS/安卓，并在 iOS 启动时恢复自动播报偏好。预连继续要求现有语音授权、开启自动播报、聊天页在前台且在线，不新增或绕过授权。

iOS 与安卓都使用现有 `/api/rtc/warm`、同一个预连播放器和房间复用机制；切换页面延迟释放、进入后台、退出页面、关闭自动播报和撤回授权均走对应释放路径。没有修改登录、会员、后端、签名或依赖。

修改同步到了实际编译目录 `/Users/zhaoqing/myprojects/LifePages`，保留原有首屏、账号和会员改动；原文件备份及同步文件指纹位于独立工作区 `artifacts/rtc-ios-parity/`。

## 检查

- 未以组件测试或构建代替实际首声延迟、听感或安卓设备验收。本轮尚无双端真实音频耗时对比。

## 延迟边界

RTC 预连接针对播报建链等待。当前访谈的一些路径还需要串行执行素材判断与独立追问生成，必要时还会纠正无效模型输出，因此文字生成也存在独立等待。此次没有通过削弱素材验收或删除追问判断来声称解决文字延迟，也没有改后端模型流程。

## 默认双端规则

按照用户新增规则，除登录、会员等已确认平台差异外，后续功能、优化和修复默认双端保持一致；只在用户明确说明仅 iOS/仅安卓时限制单端。规范写入 `AGENTS.md`，`agent.md` 为统一入口，原项目和独立工作区均已同步。
