# 陪伴访谈的上下文转换回复

分支：`ios/book-modes-20261123`；修改前提交：`36a2009`。开始时工作区干净，fetch 后合入 origin/main 返回 Already up to date。共享范围：`server/interview_v2.py`、两个后端测试文件和本文。没有改 Flutter 页面、账号、会员、RTC、原生或依赖。

## 行为

- 正常达标后进入下一主题：素材判断的同一次模型调用同时生成 `next_chapter_reply`，简短回应原话并引出下一预设题。有效结果直接复用，不为正常换章额外串一次模型请求。
- 手动“下一章节”或明确换新话题：选定下一主题的未用题，再把最近对话和选中题交给模型写承接。全部主题后返回待补主题也使用同一路径。
- 刷新最新未回答的问题：保留当前主题素材，从未用题中选新题，携带最近上下文生成承接，原气泡原子替换。被替换气泡不放入用于总结的历史，已尝试题记录继续保留。
- 题库耗尽仍可生成额外故事入口，随后同样生成上下文承接。
- 模型写承接，可总结、理解或克制共情；没有足够事实时简短过渡，不强行总结，不虚构关联，不把助手问题里的假设当成用户经历。
- 最终问题必须等于程序选中的预设题/已验证额外题，模型不得改选题方向。首次真实验收发现自由改写可能绕回旧题，因此最终采用“模型生成承接，程序固定选中题”的约束，违规结果重新生成，仍失败则返回可重试错误。
- 正常成章仍需至少 301 有效字及素材质量、故事收束；提前换章仍按 30 字规则，当前主题素材和原声不清空。进入新主题计数正常归零。
- 转换回复完成后，章节整理继续异步执行，不等待标题或正文生成。客户端继续使用现有文字、刷新、缓存和 RTC 播报流程，双端无需增加独立协议。

## 一致性与失败

随机顺序、题目 ID、覆盖记录和修订号保持原流程，不改访谈文档和数据库结构。刷新保持书籍锁、原文/修订检查、幂等请求和原子提交；模型失败不消耗题目或改变已提交进度。
