# 我的页面：加载与布局优化

原问题是底部导航每次进入“我的”都会递增 profileVersion，通过新的 Key 销毁页面，并重新等待人物详情和人物列表两个请求；人物详情还包含全部聊天消息。网络请求慢时页面只显示转圈。

本次改动：

- 保持 IndexedStack 内“我的”状态和滚动位置；按人物 ID 使用稳定 Key。
- 页面常驻内存，并以设备与服务器分别隔离的私有文件缓存回忆录概览。先呈现已有内容，再后台更新；缓存损坏或写入失败不会阻止联网读取。
- 一分钟内反复进入不重复请求。同一人物的并发刷新共用一个请求。聊天完成、编辑资料或章节后会更新相关内容；应用恢复到前台也会检查是否需要刷新。
- 新增鉴权 GET /api/people/{pid}/memoir，一次返回人物资料、章节、记录数量和讲述者列表，不返回聊天正文。旧接口兼容保留。
- 首次无缓存时使用资料与书封面占位；联网失败提供重试，并保留可用的旧内容。下拉可以手动刷新。
- 视觉沿用聊天页配色，区分讲述者资料、记录数量、书封面与章节列表；原有编辑、生成、导出、原声分享及旧录音入口保留。我的页导航展开至全宽。

验证包括慢网缓存显示、反复切换不重复请求、离线与重启恢复、新聊天触发更新、空态和首次错误恢复、文件缓存损坏与账号隔离；服务端验证统计及鉴权隔离。静态检查、14 项 Flutter 测试、12 项服务端测试和 iOS 不签名编译通过。线上使用临时虚构资料验证接口不返回聊天正文，随后清理了临时账号。没有启动模拟器。

界面图 artifacts/my-page-headless.png 为实际组件无设备渲染，使用虚构展示数据。
